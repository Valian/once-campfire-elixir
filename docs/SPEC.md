# Campfire on Phoenix — implementation spec

Target: a from-scratch Phoenix (controllers + HEEx, no LiveView) reimplementation of ONCE Campfire that
(a) opens the Rails app's SQLite database and Active Storage directory unchanged, (b) serves the
Rails app's compiled CSS/JS unchanged, (c) speaks Action Cable on `/cable`, and (d) passes this repo's
benchmark harness (`bench/run`, a macOS port of once-campfire-rust's `bench/run`).

Conventions in this document

- "Rails" = the reference app. The benchmark's reference image and seed are built from
  `basecamp/once-campfire@90b3300` (the SHA once-campfire-rust pins; see `bench/make-seed`). The
  scratchpad clone is `254dd1d`, which differs only in preloading/perf internals (same HTML, same
  behavior); file references below are to either.
- `{x}` = interpolated value; HTML attribute values are HTML-escaped (`& < > " '` → `&amp; &lt; &gt; &quot; &#39;`) unless noted.
- `[UNSURE]` = not verified against running Rails; verify before relying on it.
- Oracles you can test against without running Rails (all generated by Rails with the bench's
  `SECRET_KEY_BASE`): `cf-rust/vectors/*.json` (crypto, storage, sessions), `cf-rust/crates/views/tests/golden/{a,b}`
  (rendered views; `b/*.json` are token lists, `a/*.html` are raw), `cf-rust/crates/richtext/tests/corpus/expected.json`
  (658 rich-text bodies → presentation HTML, plain text, editor value, mentions). `bench/seed/` is a real
  seed (DB + storage + `labels.json`) — use it in tests.

### 1.3 Loadgen commands, exact requests

Loadgen = `bench/loadgen/src/main.rs`. Plain HTTP/1.1 via hyper, keep-alive, no `User-Agent` (unless `--user-agent`),
no `Accept` header on GETs, 30 s per-request timeout (counts as error, drops the connection). A response with
`connection: close` makes it reconnect. Status < 400 counts as "ok"; the harness only prints statuses.

**login** (once per rep)
1. `GET /session/new` (no cookies). Collect every `Set-Cookie` name=value (first `;`-segment). Extract CSRF with regex
   `<meta name="csrf-token" content="([^"]*)"` (attribute order and single spaces matter; missing → empty string).
2. `POST /session`, headers `cookie: {jar}`, `content-type: application/x-www-form-urlencoded`, `sec-fetch-site: same-origin`;
   body `email_address={e}&password={p}&authenticity_token={token}` (percent-encoded, unreserved `A-Za-z0-9-_.~` kept).
   **No `x-csrf-token` header** → the token must be accepted from the form field named `authenticity_token`.
3. Must answer **302** and the merged jar must contain a cookie named **`session_token`**. Output: the joined jar
   (`a=1; b=2`), used verbatim as `Cookie:` for everything that follows. Later `Set-Cookie`s are ignored.

**scrape**
1. `GET /rooms/{ROOM}` with the cookie; then `GET /users/me/sidebar`; concatenate both bodies.
2. `csrf` = same meta regex (first match, from the room page). Used later for `x-csrf-token` and `authenticity_token`.
   **The token must stay valid for the login cookie jar** (see trap T3).
3. `streams` = every match of `<turbo-cable-stream-source channel="([^"]+)" signed-stream-name="([^"]+)"`
   (exactly this attribute order, `channel` first, one space), deduped, as `channel|name`; the name is
   unescaped for `&amp; &quot; &#39;` only. Rails yields 3: `RoomMessagesChannel` (room page) and two
   `Turbo::StreamsChannel` (sidebar: `rooms` and `{user gid}:rooms`).
4. `css` = first match of `href="(/assets/[^"]+\.css)"` (Rails: `/assets/_reset-{digest}.css`).

**http** routes (each: 2 s warm-up at c=4, then `HTTP_CONCS` × `HTTP_SECS`; cookie on every request;
`accept-encoding: gzip`):

| name | request | Rails result |
|---|---|---|
| room_show | `GET /rooms/{ROOM}` | 200 full page (~460 KB raw, ~44 KB gzip) |
| messages_page | `GET /rooms/{ROOM}/messages?before={BEFORE}` | 200 HTML fragment of 40 messages (~35 KB gzip) |
| sidebar | `GET /users/me/sidebar` (no `Turbo-Frame` header → full layout) | 200 (~6 KB gzip) |
| search | `GET /searches?q=coffee` | 200 (~17 KB gzip) |
| avatar | `GET /users/{avatar_tokens.jason}/avatar` (no `?v=`) | 200 `image/webp` (3364 B file) |
| static_css | `GET {css}` | 200 (~650 B gzip) |
| up | `GET /up` (cookie sent too) | 200 |
| post_message | `POST /rooms/{WRITE_ROOM}/messages` | 200 turbo-stream (~2 KB gzip) |

post_message request: headers `cookie`, `content-type: application/x-www-form-urlencoded`,
`accept: text/vnd.turbo-stream.html, text/html, application/xhtml+xml`, `x-csrf-token: {csrf}`, `sec-fetch-site: same-origin`,
`accept-encoding: gzip`; body `message[body]=bench write {i}&message[client_message_id]={hex nonce}&authenticity_token={csrf}`.
Body is plain text, not HTML. Concurrency up to 64 writers.

**cable** (CABLE_CLIENTS = 100, 500, 1000; all clients use David's one cookie)
- Each client: `GET ws://127.0.0.1:{PORT}/cable`, headers `Cookie: {jar}`, `Origin: http://127.0.0.1:{PORT}`,
  `Sec-WebSocket-Protocol: actioncable-v1-json, actioncable-unsupported` (+ Host, Upgrade, Key, Version 13).
  tungstenite rejects the handshake unless the 101 response carries **`Sec-WebSocket-Protocol: actioncable-v1-json`**.
  50 handshakes in flight at a time.
- After connecting (does not wait for welcome) it sends, in order, `{"command":"subscribe","identifier":I}` for:
  1. `{"channel":"PresenceChannel","room_id":486777696}` (room_id is a JSON number)
  2. `{"channel":"UnreadRoomsChannel"}`
  3. `{"channel":"HeartbeatChannel"}`
  4–6. `{"channel":C,"signed_stream_name":N}` for each scraped `C|N`.
  The identifier string is serde_json output (sorted keys = the order shown, no spaces); **echo it back verbatim** (browsers send other key orders/extra keys).
- A client is "ready" when it has seen as many frames containing the substring `confirm_subscription` as it sent
  subscribes (6). One reject ⇒ that client never counts. Wait ≤ max(120 s, clients/200 s).
- Delivery detection: **any text frame** is scanned for `bmk(\d+)z`; each seq counts once per client. Nothing else in a frame matters.
- Paced phase: 30 posts, one every 200 ms, `POST /rooms/{ROOM}/messages` (same request shape as post_message,
  body `fanout bmk{seq}z`), wait ≤ 20 s until every ready client got every seq. Latency = post start → last client receipt.
- Saturated phase: 4 closed-loop posters for 15 s, then drain ≤ 60 s. `delivered_msgs_per_sec` = seqs received by *all* ready clients / span.
- So for a fan-out to count, the room's message broadcast must reach all 1000 sockets of the same user with the
  message text verbatim inside the frame (JSON string escaping is fine; HTML entities/tag splits inside `fanout bmk12z` are not).

**upload** (5 reps, room = `WRITE_ROOM`)
- `POST /rooms/{hq}/messages`, `content-type: multipart/form-data; boundary=----bench{nonce}`,
  `accept: text/vnd.turbo-stream.html, text/html`, `x-csrf-token`, `sec-fetch-site: same-origin`, cookie, no accept-encoding.
  Parts: `authenticity_token`, `message[client_message_id]`, `message[attachment]` (filename `black_hole.jpg`,
  `Content-Type: image/jpeg`, 505 420 bytes, 3840×2160). **No `message[body]` part.**
- Takes the **first** `<img[^>]+src="([^"]+)"` in the response body, unescapes it, then `GET`s it (cookie, no accept-encoding),
  following up to 5 `Location` redirects (3xx). Records final status and byte count. **It does not poll.**
- Trap T1: in Rails markup the first `<img>` in a message is the **creator's avatar** (`/users/{token}/avatar?v=…`,
  David's initials SVG, 630 bytes), not the thumbnail. So the "thumbnail served" time is really POST time
  (Rails generates the 1200×800 thumbnail synchronously inside the POST) + one avatar GET. Keep avatar-first markup;
  decide deliberately whether the thumbnail is generated in-request (Rails-comparable) or lazily (§10).

### 1.4 What the harness reports

Per route × concurrency: rps, p50/p90/p99/max, statuses, errors, avg_bytes. Cable: ready, failed,
connect_secs, paced latency (post, per_client, all_clients), saturated throughput. Upload: post_ms, thumb_ms, total_ms.
Reference numbers on this Mac (M1 Pro, `--cpus 4`, c=16): room 122 rps, messages 221, sidebar 363,
search 234, POST 159, cable-100 paced p50 41 ms; the official Elixir port: 571 / 747 / 571 / 816 / 342, p50 27 ms.

## 2. Data model (SQLite, `db/schema.rb` unchanged)

Open `/rails/storage/db/production.sqlite3`. Rails connection settings: `foreign_keys=ON`, `journal_mode=WAL`,
`synchronous=NORMAL`, `busy_timeout=5000`, transactions `BEGIN IMMEDIATE`; Rails 8 also sets `mmap_size=128MB`,
`journal_size_limit=64MB`, `cache_size=2000` [UNSURE exact defaults]. Do not run migrations; do not add columns.
Additive indexes are fine (Rails ignores them): add `CREATE INDEX IF NOT EXISTS index_messages_on_room_id_and_created_at ON messages(room_id, created_at)`
— every room page sorts by created_at and only `index_messages_on_room_id` exists.

### 2.1 Encodings (apply to every table)

- Primary keys: `integer PRIMARY KEY AUTOINCREMENT` (sqlite_sequence). Fixture ids are large hashes (e.g. 486777696); new ids continue from max.
- **datetime(6) columns are TEXT `YYYY-MM-DD HH:MM:SS` in UTC, followed by `.ffffff` only when microseconds ≠ 0**
  (Rails `quoted_date`; truncated to µs). Rows created by `insert_all` (memberships) carry SQLite
  `STRFTIME('%Y-%m-%d %H:%M:%f','NOW')` (3 fractional digits). All range comparisons (`created_at < ?`) are string
  comparisons in SQL, so **write and bind the same format** (never ISO `T`/`Z`). Parse all three variants on read.
- `json` / `text` metadata columns hold JSON text. Booleans don't occur outside JSON.
- Timestamps you write: `created_at`/`updated_at` = now (µs).

### 2.3 Associations and derived queries

- `user.rooms` = rooms JOIN memberships ON user_id. `reachable_messages` = messages in user's rooms (including invisible-involvement rooms).
- `room.users` via memberships. `Room.original` = `ORDER BY created_at LIMIT 1` over **all** rooms; `user.rooms.original` = same within the user's rooms.
- `Rooms::Open` rooms: on creation (and on conversion to Open) every active user gets a membership (`INSERT … ON CONFLICT DO NOTHING`, involvement `mentions`). New users get memberships in all open rooms.
- Room display name: non-direct → `name`; direct → names of members except `for_user`, `Enumerable#to_sentence` (`A`, `A and B`, `A, B, and C`), or `for_user.name` if empty. In message partials `for_user = nil` (all members).
- `Rooms::Direct.find_or_create_for(users)`: the direct room whose member-id set equals the given set (do it in SQL, Rails scans all), else create with all as members (involvement `everything`).

### 2.4 Active Storage layout

| Attachment | record_type / name | Variant |
|---|---|---|
| Message file | `Message` / `attachment` | thumb: `resize_to_limit [1200, 800]`, format = blob default |
| User avatar | `User` / `avatar` | square: `resize_to_limit [512, 512]`, `format: :webp` |
| Account logo | `Account` / `logo` | large 512² png, small 192² png |
| Variant image | `ActiveStorage::VariantRecord` / `image` → blob of the generated file | |
| Video preview frame | `ActiveStorage::Blob` (the video blob id) / `preview_image` → jpg blob | variants of that image: `{format: :webp}` and poster `{format: :webp, resize_to_limit: [1200,800]}` |

- File path: `/rails/storage/files/{key[0,2]}/{key[2,4]}/{key}` (e.g. `2y/en/2yenb2ld…`). No extension.
- New blob: key = 28 random chars from `0-9a-z`; checksum = Base64(MD5(bytes)); metadata after analysis:
  images `{"identified":true,"width":W,"height":H,"analyzed":true}` (ints); videos add `duration`, `display_aspect_ratio`, `audio`, `video`, width/height as floats; others `{"identified":true,"analyzed":true}`.
  Variant blobs in the seed have `{"identified":true}` only.
- Content type: sniffed (Marcel) over declared; filename sanitized (`/ \ : ; | % $ < > ? * " \t\r\n` → `-`, leading RTL marks dropped — see `cf-rust/vectors/storage.json filenames`).
- `variable?` content types: png gif jpeg tiff webp avif heic heif (bmp/ico/psd removed). `previewable?`: video/* (ffmpeg). Web images (keep their format for variants): png jpeg gif webp; other variable types → png.
- Variant lookup = `variant_records(blob_id, variation_digest)` → attachment(`ActiveStorage::VariantRecord`, id, `image`) → blob → file.
  `variation_digest = Base64(SHA1(Marshal.dump(transformations)))`, transformations ordered with `format` first.
  Symbol vs string values digest differently. Values you need (all verified in the seed/vectors):

### 2.5 FTS

- On message create: `INSERT INTO message_search_index(rowid, body) VALUES (id, plain_text_body)`;
  update: `UPDATE … SET body=? WHERE rowid=?`; destroy: `DELETE … WHERE rowid=?`.
- `plain_text_body` = rich text → plain text (§9.4), or attachment filename if blank, or `""`.
- Query: `SELECT messages.* FROM messages JOIN message_search_index idx ON messages.id = idx.rowid
  WHERE messages.room_id IN (user's rooms) AND idx.body MATCH ? ORDER BY messages.created_at` → last 100 (i.e. `DESC LIMIT 100`, reversed).
  The `?` is `params[:q].gsub(/[^[:word:]]/, " ")` (Unicode letters/digits/underscore kept, everything else → space).
  Rails 500s on bare FTS operators (`NOT`, `AND`…); quoting each term (`"term"`) is an acceptable divergence.

## 3. Rails-compatible signing (what you must reproduce)

All keys: `PBKDF2-HMAC-SHA256(password = SECRET_KEY_BASE (the hex string as bytes), salt = S, iterations = 1000, length = 64)`
(`:crypto.pbkdf2_hmac(:sha256, skb, salt, 1000, 64)`; cache per salt). Message format: `{data}--{hexdigest}` where
`hexdigest = lowercase hex HMAC(key, data)` over the *encoded* data string. Reading: split at the last `--`, constant-time compare.

| Use | Salt | HMAC | data encoding | payload | Needed for |
|---|---|---|---|---|---|
| Avatar token (`user.signed_id(purpose: :avatar)`) | `active_record/signed_id` | SHA256 | Base64 **url-safe, no padding** | `{"_rails":{"data":<user_id int>,"pur":"user/avatar"}}` | **verify** labels' tokens; generate in `<img src>` |
| Turbo signed stream name | `turbo/signed_stream_verifier_key` | SHA256 | Base64 strict (padded) | JSON string of the stream name, e.g. `"rooms"` | generate; verify on subscribe (format is ours to choose, but matching Rails is free) |
| SGID (mention attachable) | `signed_global_ids` | SHA1 | Base64 url-safe **padded** | `{"_rails":{"data":"gid://campfire/User/<id>?expires_in","pur":"attachable"}}` | generate for autocomplete; parse (not verify) when rendering |
| Active Storage ids/keys | `ActiveStorage` | SHA1 | Base64 strict | `{"_rails":{"data":<blob_id>,"pur":"blob_id"}}`; variation `{"_rails":{"data":{"format":"jpg","resize_to_limit":[1200,800]},"pur":"variation"}}`; disk key `{"_rails":{"data":{"key":…,"disposition":…,"content_type":…,"service_name":"local"},"exp":"…Z","pur":"blob_key"}}` | URLs (ours to choose; Rails-compatible is cheap) |
| Signed cookie (`cookies.signed[:session_token]`) | `signed cookie` | SHA1 | Base64 strict, legacy envelope `{"_rails":{"message":"<b64 of JSON-dumped value>","exp":"2046-…Z","pur":"cookie.session_token"}}` | | **not needed** (we issue our own cookie) |

## 4. Authentication, sessions, CSRF

### 4.1 Flow (Rails behavior)

- `GET /session/new` (unauthenticated OK): sign-in page; if no users exist Rails redirects to `/first_run` (out of scope: render a static "not set up" page).
- `POST /session` params `email_address`, `password`: user must be `status=active` and bcrypt-match (cost 12, `$2a$`;
  max 72 bytes). Rails also rate-limits **10 per IP per 3 min** → 429 + re-render. Failure → **401** re-render `sessions/new`
  with flash alert "Too many requests or unauthorized." (panel gets class `shake`). Success:
  `INSERT sessions(user_id, token, user_agent, ip_address, last_active_at=now)`, set cookie, **302** to
  `session[:return_to_after_authenticating]` (stored when an unauthenticated request was redirected) or `/` (absolute URL).
- Cookie (Rails): `session_token={signed token}; path=/; expires=+20 years; HttpOnly; SameSite=Lax` (no `Secure` with DISABLE_SSL).
  Rails re-sets it on every authenticated response; you needn't. **Our value format is free** (e.g. the raw 24-char
  token HMAC-signed by us); only the name `session_token` is part of the contract.
- Every authenticated request: look up `sessions.token`; if `last_active_at` older than 1 h, update `last_active_at`,
  `user_agent`, `ip_address`. Session row missing / user not active → treat as signed out. Cache the session→user lookup (ETS) — it's on every request and every cable connect.
- Unauthenticated HTML request → 302 to `/session/new` (store return URL). Avatars are behind auth in Rails too.
- `DELETE /session` (sign out): delete session row, clear cookies, disconnect the user's cable connections
  (`{"type":"disconnect","reason":"remote","reconnect":true}`), 302 `/`. Param `push_subscription_endpoint` deletes that push subscription.
- Bots (`role=2`) can't use the web UI (403); bot API is out of scope.
- Banned IP (`bans.ip_address = remote ip`) on non-GET/HEAD → 429 empty.
- Other cookies Rails sets: `_campfire_session` (encrypted session store: CSRF secret, return_to, flash) and
  `last_room={room_id}` (permanent, on room show; read by `/` and search's back link).

### 4.2 CSRF contract

- Every full-layout page has `<meta name="csrf-param" content="authenticity_token">` and `<meta name="csrf-token" content="{token}">`
  (in that form — the loadgen regex needs `name` then `content`). Turbo frame layout too.
- Turbo sends `X-CSRF-Token: {meta token}` on every non-GET fetch; the composer's XHR upload (`models/file_uploader.js`)
  reads `meta[name=csrf-token]` and **throws if it's missing** — so always render the meta.
- Forms (`form_with`/`button_to`) render `<input type="hidden" name="authenticity_token" value="…">`. Because Turbo
  always sends the header, cached message fragments may omit or carry a stale field value (Rails' cached fragments
  carry the first renderer's token) — accept a request if **either** the header or the `authenticity_token` param is valid.
- Plug.CSRFProtection reads `_csrf_token`; either copy `authenticity_token` into it before the plug or write a small verifier.
- Recommended stateless design: token secret = HMAC(server key, anon-or-session id) masked per render; for the
  login form use a pre-session cookie set by `GET /session/new`. Whatever you pick, see trap T3.

### 8.4 Messages page (`GET /rooms/:room_id/messages`)

- `before=ID`: messages with `created_at < that.created_at`, `DESC LIMIT 40`, reversed. `after=ID`: `created_at >`, `ASC LIMIT 40`.
  Neither: last 40. `ID` must belong to the room (404 otherwise).
- Body = concatenated message partials, **no layout**, `text/html`. Empty → 204.
- Rails adds `fresh_when(@messages)`: weak ETag + `Last-Modified: max(updated_at)`; 304 on match. The loadgen never revalidates.

### 8.5 Refresh (`GET /rooms/:room_id/refresh?since={ms}&reason=…`)

`since` → time = epoch ms. new = `created_at > since ORDER BY created_at ASC LIMIT 40`; updated = (not in new) `updated_at > since`, last 40 by created_at.
Response `text/vnd.turbo-stream.html`: if new non-empty, one `<turbo-stream action="append" target="messages_rooms_{type}_{id}"><template>{partials}</template></turbo-stream>`;
then for each updated `<turbo-stream action="replace" target="message_{cmid}"><template>{partial}</template></turbo-stream>`. Empty body if neither.

### 8.6 Create / update / destroy (server side)

Create (`POST /rooms/:room_id/messages`, params `message[body]`, `message[attachment]`, `message[client_message_id]`):
1. Membership check (any member may post, including involvement invisible).
2. One transaction: insert message (`client_message_id` param or UUIDv4), rich text row if body present,
   blob + attachment if file, touch room `updated_at`.
3. After commit: `memberships SET unread_at = message.created_at, updated_at = now WHERE room_id = ? AND involvement <> 'invisible'
   AND (connected_at IS NULL OR connected_at < now-60s) AND user_id <> creator` (NULL involvement is excluded by SQL semantics, as in Rails);
   FTS insert; (push job — out of scope; webhooks — out of scope).
4. Attachment: analyze, then thumbnail (images: thumb variant; videos: preview image + `{format: :webp}` variant) — Rails does this synchronously before responding.
5. Broadcast (§11.4): append to room stream; `{"roomId": id}` to `user_{uid}_unreads` for **every member** (including the author).
6. Respond 200 `text/vnd.turbo-stream.html`: `<turbo-stream action="append" target="messages_rooms_{type}_{room_id}"><template>{partial}</template></turbo-stream>`.

Update (owner or admin; `can_administer?(message)` = admin or creator): update rich text; touch message & room; FTS update;
broadcast replace of `presentation_message_{cmid}` with the presentation div (`maintain_scroll="true"`); 302 to `/rooms/{rid}/messages/{id}`.

Destroy: delete boosts, rich text, attachment (+ files, async), FTS row, message; touch room; broadcast remove;
respond `<turbo-stream action="remove" target="message_{cmid}"></turbo-stream>`.

Edit frame (`edit.html.erb`): text → `<turbo-frame id="edit_message_{cmid}"><div class="message__body position-relative" data-controller="scroll-into-view">…<form id="form_message_{cmid}" data-controller="form" data-action="lexxy:file-accept->form#preventAttachment keydown.esc->form#cancel keydown.ctrl+enter->form#submit:prevent keydown.meta+enter->form#submit:prevent" action="/rooms/{rid}/messages/{id}" method="post"><input type="hidden" name="_method" value="patch">…<lexxy-editor … aria-label="Edit message" autofocus="autofocus" … name="message[body]" value="{editable body, HTML-escaped}">…</form>…<form id="delete_form_message_{cmid}" data-turbo-frame="edit_message_{cmid}" … _method=delete></form></div></turbo-frame>`;
attachment → presentation + delete button only. Port the ERB. Editable body = stored body with each attachment's
`content-type` reset from its attachable and `content` = rendered attachable partial (mentions: the `users/_mention` span) [see cf-rust `richtext::editable_value`].

## 9. Rich text (Action Text + Lexxy)

### 9.1 Storage

`action_text_rich_texts.body` holds HTML as submitted by Lexxy (`<p>…</p>`, `<strong>`, `<em>`, `<s>`, `<u>`, `<mark>`,
`<code>`, `<pre data-language="x">` with `<br>` lines, `<blockquote>`, `<ul>/<ol>/<li>`, `<h1>`, `<a href>`,
`<figure class="lexxy-content__table-wrapper"><table>…`, `<hr>`), or plain text (the loadgen posts plain text),
or Trix-era `<div>` markup. Rails canonicalizes on save: each `<action-text-attachment>` keeps its attributes but loses
its inner HTML. Attachments in bodies:
- Mention: `<action-text-attachment sgid="{sgid}" content-type="application/vnd.campfire.mention" content="{escaped mention span}"></action-text-attachment>`
- Unfurl (Lexxy): `content-type="application/vnd.actiontext.opengraph-embed" content="{escaped <actiontext-opengraph-embed>…}"`;
  Trix-era: attributes `url`, `href`, `filename`, `caption` on the node.

Storing: you may store the submitted HTML after stripping attachment inner HTML; don't canonicalize anything else.

### 9.2 Presentation pipeline (text messages)

Final output is wrapped as `<div class="lexxy-content">\n  {html}\n</div>\n`. Steps (Rails):
1. Parse body as an HTML fragment.
2. `RemoveSoloUnfurledLinkText`: if there is exactly one opengraph attachment and the message's plain text equals its href
   (Twitter/x.com URLs normalized: host → twitter.com, query dropped), remove the link-only text: Lexxy bodies drop every `<p>` without an attachment; Trix bodies replace each `<div>`'s content with the embed.
3. `SanitizeTags`: remove (with contents) every element not in: `a abbr acronym address b big blockquote br cite code dd del dfn div dl dt em h1–h6 hr i ins kbd li ol p pre samp small span strong sub sup time tt ul var s u mark table thead tbody tfoot tr th td action-text-attachment figure figcaption`.
4. `SanitizeAttributes`: Loofah safe-list scrub (unsafe URI schemes removed, `on*` dropped) with those tags and attributes
   `abbr alt cite class datetime height href lang src title width xml:lang` + attachment attrs `sgid content-type url href filename filesize width height previewable presentation caption content` + `controls poster data-language style value start` [style allowed here but dropped later].
5. Render attachments: replace each `<action-text-attachment>`'s inner HTML with its attachable's partial:
   - **Mention** (content-type `application/vnd.campfire.mention`, or any sgid resolving to a User): resolve the sgid **without
     verifying the signature** — Base64-decode the part before `--` (strict, then url-safe), JSON, take `_rails.data`
     (`gid://campfire/User/{id}?expires_in`) or, for Rails-7 Marshal sgids, `_rails.message` → base64 → regex `gid://campfire/[^/]+/\d+`.
     If it's a User that exists: `<span class="mention" sgid="{user.attachable_sgid}">{avatar_tag(user)} {user.name}</span>`. Deleted user → Rails renders nothing useful [cf-rust renders ☒].
   - **Opengraph embed**: `<figure class="attachment attachment--content attachment--og"><actiontext-opengraph-embed><div class="og-embed gap {og-embed--twitter-avatar if url starts with https://pbs.twimg.com/profile_images}"><div class="og-embed__content"><div class="og-embed__title">{link_to_if href, truncate(title, 280, "…"), href, rel: noreferrer, target: _blank}</div><div class="og-embed__description">{truncate(description, 560, "…")}</div></div>{if url: <div class="og-embed__image"><img src="{url}" class="image center" alt=""></div>}</div></actiontext-opengraph-embed></figure>`.
     href/url/title/description come from node attributes (Trix: `href url filename caption`) or from parsing `content`
     (`.og-embed__title a[href]`, `.og-embed__image img[src]`, title text, `.og-embed__description` text). URLs must be absolute http(s) with a named host (last label has a letter, not `0x…`, no `%`) different from the request host; otherwise dropped. Invalid (no href?) → not an embed [UNSURE].
   - Others (blobs, remote images, raw content attachments) — not produced by the composer; render their caption or nothing.
6. Action Text layout + sanitize (allowed tags = Rails defaults + `action-text-attachment figure figcaption video audio source embed table tbody tr th td` + editor tags; attributes as in step 4).
7. `auto_link(html, target: "_blank")` re-sanitizes with **Rails default tags (`a abbr acronym address b big blockquote br cite code dd del dfn div dl dt em h1–h6 hr i img ins kbd li mark ol p pre samp small span strong sub sup time tt ul var`) + `s u mark table thead tbody tfoot tr th td`** and attributes `abbr alt cite class datetime height href lang src title width xml:lang data-language`. Disallowed tags are **unwrapped** (children kept): so `action-text-attachment`, `figure`, `actiontext-opengraph-embed` disappear, and `sgid`, `data-turbo-frame`, `aria-hidden`, `rel`, `target`, `style` attributes are stripped.
   Then bare URLs in text (regex `(?:(?i:(ed2k|ftp|http|https|irc|mailto|news|gopher|nntp|telnet|webcal|xmpp|callto|feed|svn|urn|aim|rsync|tag|ssh|sftp|rtsp|afs|file):)//|(?i:www)\.[a-zA-Z0-9_])[^\s< "]+`, trailing punctuation trimmed, not inside existing `<a>` or tags) become `<a target="_blank" href="{url}">{url}</a>`; emails likewise `mailto:`.

Effective results (from the Rails corpus):
```
"First post!"                       → <div class="lexxy-content">\n  First post!\n</div>\n
"<ul><li>One</li><li>Two</li></ul>" → <div class="lexxy-content">\n  <ul><li>One</li><li>Two</li></ul>\n</div>\n
mention of David                    → …<p>Hey <span class="mention"><a title="David – Founder" class="btn avatar" href="/users/1"><img src="/users/{tok}/avatar?v=…" width="48" height="48"></a> David</span> how are you?</p>…
<div>Visit https://example.com/?a=1&b=2 …</div> → <div>Visit <a target="_blank" href="https://example.com/?a=1&amp;b=2">https://example.com/?a=1&b=2</a> …
```
Note: in presentation the mention span has **no `sgid`** and its avatar `<a>` has no `data-turbo-frame`. The JS mention highlighter looks for
`.mention img[src^="/users/{current_user.id}/avatar"]`, which never matches token URLs — mention highlighting is
effectively dead in Rails too; don't spend time on it (or fix it deliberately).

Use the corpus (`cf-rust/crates/richtext/tests/corpus/{inputs.yml,expected.json}`, 658 cases incl. XSS, Trix, Lexxy, embeds; placeholders expanded with the bench secret) as the conformance test. Exact whitespace/serialization only needs to be HTML-equivalent.
Implementation hint: Floki/`lazy_html`/a NIF parser + one allowlist walker that applies steps 3–7 in a single pass is enough; the
final allowlist (step 7) bounds everything, so steps 4 and 6 only matter for which content survives step 3/5.

### 9.3 Emoji-only

### 9.4 Plain text (`to_plain_text`)

Attachments first become their plain representation (mention → `@{name}`, embed → `""`, others caption/filename),
then: `p`, `h1` → children + `\n\n`; `ul`/`ol` → block (+ leading `\n` if nested); `li` → `{indent}{• | N.} {text}\n`;
`br` → `\n`; `div` → children + `\n`; `blockquote` → `“text”` + `\n\n`; `figcaption` → `[text]`; `script/style` dropped;
text nodes as-is; finally strip leading/trailing newlines (`chomp`). Examples: `<p>Hello <s>x</s></p><pre>def x<br>end</pre>` → `"Hello x\n\ndef x\nend"`; list → `"• One\n• Two"`.
Used for: FTS index, emoji detection, `/play` detection.

## 10. Attachments, thumbnails, avatars

### 10.1 Upload handling

Multipart `message[attachment]` (single file per message). Stream to a temp file; compute MD5; sniff type; create
blob (key, filename sanitized, content_type, byte_size, checksum, metadata `{"identified":true}`), copy into
`files/{k0k1}/{k2k3}/{key}`; attachment row (`Message`/`attachment`). Analyze: images → width/height (libvips header,
EXIF-rotated dims [UNSURE]); videos → ffprobe (width, height, duration, display_aspect_ratio, audio, video). Set `analyzed: true`.
Thumbnail (variable images): libvips `thumbnail`-style resize to fit within 1200×800 **only if larger**
(`resize_to_limit`), keep format for png/jpeg/gif/webp (output filename `{base}.{format}`), else png; strip metadata;
store as variant (§2.4). Videos: `ffmpeg -i in -vf 'select=eq(n\,0)+eq(key\,1)+gt(scene\,0.015),loop=loop=-1:size=2,trim=start_frame=1' -frames:v 1 -f image2 -` → jpg preview image blob
(`{base}.jpg`, attached as `preview_image` to the video blob) → `{format: :webp}` variant. The poster used by the page is
`{format: :webp, resize_to_limit: [1200,800]}` of the preview image, generated on first request if missing.
Byte-identical output to Rails is not required. Elixir: `vix`/`image` (libvips NIF) and `System.cmd("ffmpeg")`.

### 10.2 Attachment presentation (`Messages::AttachmentPresentation`)

- dims = metadata width/height; if both ≤ 1200×800 → as-is (ints), else scaled by `min(1200/w, 800/h)` → **floats**.
- container: `<div class="max-inline-size center flex overflow-clip" style="width: {w/2}px; aspect-ratio: {w/h float};">`
  (Ruby number formatting: ints divide as ints `640/2 → 320`, floats print with `.0`: `600.0px`, `1.7777777777777777`, `1.0`);

- Other files (and non-variable images like bmp): `<div class="flex-inline align-center gap-half"><img class="colorize--black" aria-hidden="true" src="/assets/common-file-text-{d}.svg" width="22" height="22"><span>{filename}</span><a class="btn message__action-btn hide-in-ios-pwa" style="--width: auto;" href="{blob redirect}?disposition=attachment"><img aria-hidden="true" src="/assets/download-{d}.svg" width="20" height="20"><span class="for-screen-reader">Download {filename}</span></a><button class="btn message__action-btn" style="--width: auto;" data-controller="web-share" data-action="web-share#share" data-web-share-files-value="{download url}"><img aria-hidden="true" src="/assets/share-{d}.svg" width="20" height="20"><span class="for-screen-reader">Share {filename}</span></button></div>`.
- URLs: blob redirect `/rails/active_storage/blobs/redirect/{signed blob id}/{filename url-escaped}`; representation
  `/rails/active_storage/representations/redirect/{signed blob id}/{variation key}/{filename}` (original blob's filename).
  Signed segments are path-escaped (`=` stays) [see cf-rust `storage/src/paths.rs`]. Since only we produce and consume these, any
  stable signed scheme works; Rails' (§3) is recommended.
- Redirect endpoints: verify → find blob → (representation: find/generate variant) → **302** to
  `/rails/active_storage/disk/{encoded key}/{filename}` (Rails: absolute URL, key expires in 5 min). Disk endpoint:
  verify key + expiry → `send_file` with `Content-Type` (dangerous types such as `text/html`/`image/svg+xml` served as
  `application/octet-stream`), `Content-Disposition: {inline|attachment}; filename="{ascii}"; filename*=UTF-8''{escaped}`
  (forced `attachment` for types not in the inline allowlist), `Cache-Control: max-age=3600, public`. Support `Range`.
  These URLs are public bearer URLs in Rails (no session check). Serving directly (200 from the redirect URL) is an
  acceptable shortcut; the loadgen follows up to 5 redirects either way.

## 11. Real time: Action Cable over WebSock

Implement as a Plug route `GET /cable` → `WebSockAdapter.upgrade/4` with a custom `WebSock` handler (not `Phoenix.Socket`:
the wire protocol differs). Use `Phoenix.PubSub` (local) for streams.

### 11.1 Handshake

- Require WebSocket upgrade; check `Origin` equals `http(s)://{Host header}` (Rails `allow_same_origin_as_host`); mismatch → 404.
- Negotiate subprotocol: pick `actioncable-v1-json` if offered and **set `sec-websocket-protocol: actioncable-v1-json` on the 101**.
- Authenticate from the `session_token` cookie (same lookup as HTTP, no `last_active_at` write). Failure: upgrade, send
  `{"type":"disconnect","reason":"unauthorized","reconnect":false}`, close.
- Success: send `{"type":"welcome"}`; then every **3 s** `{"type":"ping","message":{unix seconds}}`. The browser client
  reconnects if it sees no ping for ~6 s, so pings are mandatory (one timer per socket, or one global ticker broadcasting a prebuilt frame).
- Frames are JSON text. No compression needed (the bench's default cable clients don't offer permessage-deflate).

### 11.2 Client commands

| Command | Shape | Server behavior |
|---|---|---|
| subscribe | `{"command":"subscribe","identifier":"<JSON string>"}` | parse identifier JSON; unknown channel → no reply (Rails logs); **already subscribed with the byte-identical identifier → ignored, no reply**; authorize; reply `{"identifier":"<same string>","type":"confirm_subscription"}` or `…"type":"reject_subscription"` |
| unsubscribe | `{"command":"unsubscribe","identifier":"…"}` | stop streams, run unsubscribe callback, no reply |
| message | `{"command":"message","identifier":"…","data":"<JSON string e.g. {\"action\":\"present\"}>"}` | dispatch `action` to the channel |

Process each connection's commands strictly in arrival order (pages send `unsubscribe` immediately followed by `subscribe`
for the same identifier when the sidebar frame reloads; reordering drops the subscription).
Outgoing broadcast frame: `{"identifier":"<identifier string>","message":<payload JSON>}` — for turbo streams the payload is a
JSON **string** of HTML; for unread/read/typing it's an object. Encode the payload once per broadcast and splice it:
`[~s({"identifier":), json_identifier, ~s(,"message":), payload_json, "}"]`.

Remote disconnect (logout, membership removal): `{"type":"disconnect","reason":"remote","reconnect":true}` then close.
Rails' internal stream for this is `action_cable/{user gid param}`; use a per-user Registry instead.

### 11.3 Channels

Names below are pubsub topics. `{room gid}` = `to_gid_param` of `gid://campfire/Rooms::{Type}/{id}`.

| Channel (identifier) | Authorize | Streams | Actions / callbacks |
|---|---|---|---|
| `HeartbeatChannel` `{}` | signed in | none | none (exists so `refresh_room` gets connected/disconnected callbacks) |
| `PresenceChannel` `{room_id}` | user is a member of room_id (else reject) | `presence:{room gid}` (nothing broadcasts to it) | on subscribe: `present`; on unsubscribe: `absent`; actions `present`, `absent`, `refresh` |
| `TypingNotificationsChannel` `{room_id}` | member | `typing_notifications:{room gid}` | `start` / `stop` → broadcast `{"action":"start"\|"stop","user":{"id":…,"name":"…"}}` to the stream (sender filters itself client-side) |
| `RoomChannel` `{room_id}` | member | `room:{room gid}` | unused by JS |
| `UnreadRoomsChannel` `{}` | signed in | `user_{id}_unreads` | none |
| `ReadRoomsChannel` `{}` | signed in | `user_{id}_reads` | none |
| `RoomMessagesChannel` `{signed_stream_name}` | name verifies, is `{gid}:messages`, gid → a Room the user is a member of | that stream name | none |
| `Turbo::StreamsChannel` `{signed_stream_name}` | name verifies **and its suffix after the first `:` is not `messages`** (guard against bypassing RoomMessagesChannel) | that stream name | none |

Presence (membership row of current user in that room):
- `present`: `UPDATE memberships SET connections = (connected? ? connections+1 : 1), connected_at = now, unread_at = NULL WHERE id = ?`
  (connected? ≡ `connected_at >= now-60s`); then broadcast `{"room_id": room_id}` to `user_{uid}_reads`.
- `absent`: connections−1 (or 0 if not connected); if result < 1 set `connected_at = NULL`.
- `refresh` (browser every 50 s): if not connected, connections+1; `connected_at = now`.
- On boot: `UPDATE memberships SET connected_at=NULL, connections=0, updated_at=now WHERE connected_at >= now-60s` (Rails does this in puma.rb).
With 1000 sockets of one user in one room every connect does a write; coalesce in memory if you like (Rails semantics only need
"connected within 60 s" and a positive count), but `unread_at = NULL` on present must persist.

### 11.4 Broadcast catalog (turbo-stream payloads)

Tag format: `<turbo-stream{ maintain_scroll="true"} action="{a}" target="{t}"><template>{html}</template></turbo-stream>`;
`remove` has no `<template>`. Extra attributes come before `action`.

| Trigger | Stream | Payload |
|---|---|---|
| message create | `{room gid}:messages` | `append` target `messages_rooms_{type}_{room_id}`, message partial |
| ↳ same | `user_{uid}_unreads` for **each member uid** | `{"roomId": room_id}` |
| message update | `{room gid}:messages` | `maintain_scroll="true"` `replace` target `presentation_message_{cmid}`, `<div id="presentation_message_{cmid}" dir="auto" data-reply-target="body" data-messages-target="body">{presentation}</div>` |
| message destroy | `{room gid}:messages` | `remove` target `message_{cmid}` |
| boost create | `{room gid}:messages` | `maintain_scroll="true"` `append` target `boosts_message_{cmid}`, boost partial |
| boost destroy | `{room gid}:messages` | `remove` target `boost_{id}` |
| open room create | `rooms` | `prepend` target `shared_rooms`, shared-room link (12.1) |
| open room update | `rooms` | `replace` target `list_rooms_open_{id}`, shared-room link |
| closed room create | `{user gid}:rooms` for each member | `prepend` `shared_rooms`, shared-room link |
| closed room update | `{user gid}:rooms` for each remaining member | `replace` `list_rooms_closed_{id}` |
| direct room create | `{user gid}:rooms` per member | `prepend` `direct_rooms`, direct link rendered for that member |
| room destroy | `rooms` | `remove` `list_rooms_{type}_{id}` |
| involvement → invisible (non-direct) | `{user gid}:rooms` | `remove` `list_rooms_{type}_{id}` |
| involvement invisible → visible | `{user gid}:rooms` | `prepend` `shared_rooms`, shared link |
| presence present | `user_{uid}_reads` | `{"room_id": id}` |
| typing | `typing_notifications:{room gid}` | `{"action":…,"user":{"id","name"}}` |

Fan-out cost to plan for (cable suite): per post, render once, 1 room-stream broadcast to 1000 sockets + 3 unread broadcasts
(watercooler members David, Jason, Bender) of which David's reaches 1000 sockets → 2000 frames/post. Rails ≈ 13k frames/s,
official Elixir ≈ 60k, Rust ≈ 300k (loadgen-bound). Use `Phoenix.PubSub.local_broadcast` (or a Registry dispatch) with the
payload as one shared refc binary; avoid per-subscriber JSON encoding, GenServer hops and Redis.

## 15. HTTP headers & caching Rails sends (ours may differ)

| Response | Rails |
|---|---|
| HTML pages, frames, turbo streams | `Cache-Control: max-age=0, private, must-revalidate`; weak ETag of the body (Rack::ETag) [UNSURE]; `Content-Type: text/html; charset=utf-8` / `text/vnd.turbo-stream.html; charset=utf-8`; `Vary: Accept-Encoding`, `Content-Encoding: gzip` (Rack::Deflater, zlib default level) when requested; `X-Version`, `X-Rev`; Set-Cookie `session_token` (+ `_campfire_session`, `last_room`) |
| messages#index | `fresh_when`: weak ETag + Last-Modified; 304; 204 if empty |
| avatar | weak ETag, `max-age=1800, public, stale-while-revalidate=604800`, served from Thruster's cache |
| account logo | `max-age=300, public, stale-while-revalidate=604800` |
| `/assets/*` | `public, max-age=2592000`, gzip by Rack::Deflater, Thruster cache |
| Active Storage redirects | 302; [UNSURE] `max-age=300, private` |
| disk files | `max-age=3600, public` |

Recommendations: gzip HTML/turbo-stream responses (the loadgen asks for it and avg_bytes is reported; zlib level 1–6 is a
CPU/size trade-off — Rails uses 6); don't compute body ETags for big pages (wasted MD5); keep `private` on authenticated pages.

## 17. Traps (read before building)

- **T1 Upload "thumbnail"** = first `<img>` of the POST response = author's avatar. Keep avatar-first markup; decide thumbnail timing deliberately (§1.3, §10.1).
- **T2 Avatar tokens** in `labels.json` are Rails signed ids; without PBKDF2-SHA256(1000)+HMAC-SHA256 verification with `SECRET_KEY_BASE` the avatar route 404s (counts as error-free 404s, wrong benchmark).
- **T3 CSRF vs. the frozen cookie jar.** Login posts `authenticity_token` (form field, no header) using the cookie from `GET /session/new`; later POSTs send the token scraped from the room page with the jar from login, and the loadgen **ignores every later Set-Cookie**. If login rotates/clears the session (phx.gen.auth's `renew_session` does `delete_csrf_token` + `clear_session`), the room page mints a new CSRF secret into a cookie the loadgen never sends → every POST 403s. The secret that validates page tokens must be derivable from the login response's cookies.
- **T4** WebSocket 101 must echo `Sec-WebSocket-Protocol: actioncable-v1-json` or tungstenite fails every client.
- **T5** A client counts only after **6** confirmations; any rejected identifier (e.g. Turbo channel guard misfiring on `rooms`, or a membership check bug on PresenceChannel) zeroes the cable suite.
- **T6** Delivery detection is a substring scan for `bmk\d+z` — message text must appear contiguously in the frame (no autolink/entity/tag injection inside it).
- **T7** Datetimes are TEXT `YYYY-MM-DD HH:MM:SS[.ffffff]`; ISO-8601 writes break `created_at < ?` ordering silently. Ecto's `:utc_datetime_usec` with ecto_sqlite3 writes ISO by default [verify `datetime_type` option] — consider raw SQL via exqlite.
- **T8** STI dom ids: `messages_rooms_closed_486777696`, `list_rooms_open_…`; message ids use `client_message_id`.
- **T9** Exact regexes: `<meta name="csrf-token" content="…"`, `<turbo-cable-stream-source channel="…" signed-stream-name="…"`, `href="/assets/….css"`. HEEx preserves attribute order — write them in that order.
- **T10** `Turbo::StreamsChannel` must reject `…:messages` names; `RoomMessagesChannel` must accept them only for members.
- **T11** Unread fan-out goes to every member's `user_{id}_unreads` (the author included); in the cable suite David's 1000 sockets get 2 frames per post.
- **T12** Variation digests are Marshal-based and symbol/string-sensitive (§2.4); match them or lookups miss and you regenerate seed thumbnails.
- **T13** Missing `messages(room_id, created_at)` index; add it.
- **T14** Turbo form submissions require a turbo-stream response or a redirect; returning 200 HTML to the composer POST breaks the UI (Turbo error), even though the loadgen would count it OK.
- **T15** `/users/me/sidebar` without `Turbo-Frame` header = full layout; with it = frame layout. Both must contain the two stream sources.
- **T16** Room "Rooms::Closed" vs Open naming leaks into gid params, dom ids and edit paths (`/rooms/closeds/:id/edit`).
- **T17** The release must start as the image's default user with bind-mounted dirs; no epmd; bounded boot (cold start is measured).
- **T18** Rails' caches (fragment cache in Redis, Thruster's HTTP cache for avatars/CSS) are part of the Rails numbers; the cheap routes are cache-bound, the page routes are render+gzip-bound.
- **T19** `room_display_name` for directs and `for_user: nil` in message partials is an N+1 in Rails (members per message); preload.
- **T20** Search uses FTS `MATCH` with user-controlled text; quote terms to avoid 500s.

## 18. Non-normative implementation notes (perf-relevant)

- SQLite: one writer process owning a write connection (all writes + their after-commit work serialized), plus a pool of
  N read connections (WAL readers run in parallel); prepared statements cached per connection; `exqlite` directly (Ecto optional).
- Render with HEEx function components compiled to iodata; never build pages by string concatenation of binaries.
- Per-message HTML cache in ETS (§8), per-boost too; page = static head iodata + cached fragments + small dynamic bits.
- Encode cable payloads once; deliver via `Registry.dispatch`/`Phoenix.PubSub` (local) to WebSock processes, which push iodata.
- gzip: `:zlib` deflate with level tuned; precompressed static assets; avatar bytes cached.
- bcrypt (cost 12 ≈ 250 ms): `bcrypt_elixir` dirty NIF; verifies `$2a$` [UNSURE, should].

## Appendix A — perf anti-patterns in the official Elixir port (`cf-elixir`, for reference only)

1. **All SQL through one GenServer** (`Campfire.DB` wraps a single exqlite connection; `DB.query/one` are `GenServer.call`s) — reads serialize behind writes; no reader pool.
2. **N+1 per message on cache miss**: `MessagesView.render_fragment` does `SELECT * FROM users`, `rooms`, `action_text_rich_texts`, then boosts and each booster, one call each (through the GenServer).
3. **Redis on the hot path in a single-node app**: every broadcast is `PUBLISH` to Redis and every socket subscribes to Redis per stream with a blocking 5 s `receive` during subscribe; fragment cache is Redis `GET`/`MGET` of Rails-Marshal-format entries decoded per request (with a 2048-entry ETS memo that's wiped wholesale when full).
4. **Per-subscriber JSON work**: Redis payloads are decoded and re-framed for every subscription of every socket (`CableFrames.frame` per delivery); local path re-encodes `Rails.json(%{identifier, message})` per recipient.
5. **Rows as string-keyed maps from `SELECT *`**, `DB.one("SELECT * FROM accounts LIMIT 1")` on many requests (layout, manifest, sidebar settings), `count(*)` of room messages on every room show.
6. **Regex/string work per request**: account version via `Regex.replace(~r/[^0-9]/, …)` per page; PWA manifest built by regex-substituting ERB source at runtime; a 600-line regex user-agent parser on every request.
7. **Per-session CSRF tokens passed into shared fragment rendering** (`render_many(messages, base, csrf)`) — either the cache leaks one user's token or the cache is per-user.
8. **Whole-body gzip in a separate pass** (`IO.iodata_to_binary(body)` then gzip) and Rack-emulation layers (`Campfire.Rack`, custom route recognition) instead of Plug pipelines.
9. **Rails-faithful extras kept on the hot path**: re-setting the `session_token` cookie on every page, Thruster + Redis + a native Resque-compatible worker in the container (idle 150 MB, 2.5 GB image).
10. Native C helpers (Gumbo HTML parser, libvips) bridged per call; fine in isolation, but combined with (1) every render waits on the DB GenServer.
